# M5 — the doors (first slice: serverd)

Date: 2026-08-04. Scope ruled by the project lead the same day; this
report records the rulings, the grounding, and the first build slice.

## Rulings

- **Streamable HTTP before stdio.** The shim's first transport is HTTP:
  the rebuild loop is restart-the-server, no client restart (stdio needs
  a Claude Code restart on each rebuild). stdio stays a few unbuilt
  lines.
- **Flight SQL cut from M5.** Not needed for testing — pyarrow reads the
  same HTTP Arrow IPC stream the cockpit door emits. It remains the
  future engine-grade door for peers; tonic stays out of the tree until
  a peer exists.
- **The door tells, skills teach.** The MCP surface is one `glossql`
  tool (statements in, outcomes out). Everything an agent must *learn* —
  SPEC.md, `grammar.ebnf`, rhai authoring with the kernel list, flow
  playbooks — ships as skills sourced from the repo artifacts, so the
  teaching layer cannot drift from the language. Everything *live*
  (declared functions, the glossary, the tables) is read through the
  language, where it is always current. A verb-tool vocabulary
  (`gloss`, `look_*`, …) was considered and rejected as a second
  surface that drifts.
- **Reads stream end to end.** Collect-then-encode buffered the whole
  result twice before the first byte left; caps hid work instead of
  preventing it. `Session::query_stream` gives the doors a batch stream
  (DataFusion `execute_stream`); `/query` encodes each batch into a
  chunked body as it arrives — memory rides one batch, no cap, a client
  that hangs up cancels the work upstream. The MCP door pulls from the
  same stream and stops at the cap, so the cap bounds the engine's
  computation, not just the rendering. The cap is a boot flag
  (`--row-cap`, default 200) and the tool description states it — it
  exists because a tool result lands verbatim in the agent's context
  window.
- **`USE` stays explicit.** No auto-`USE` of the workspace's dataset:
  in the authenticated future the used dataset derives from the JWT,
  so the current shape is the one that survives.
- **Acceptance test.** Define the workspace statically (fixture 11's
  declaration block as bootstrap), then one agent with skills drives
  add-source end to end through the door — probe, recipe, land,
  extractions, glossing the tagged columns, framing the source. The
  rhai-writing skill (agents extend the system) is the level after.

## Grounding (v0.3, verified in `../dataraum-context`)

- **No MCP server exists to port** — built twice (stdio, then
  streamable HTTP with bearer auth), then deliberately deleted; ADR-0002
  bans MCP as a transport there. What survives is the tool vocabulary
  (~25 TanStack tools, fenced per conversation kind).
- **No actor identity exists** — human auth is verified then discarded
  (`auth/gate.server.ts:60-91`); the only agent-vs-human signal is a
  `role` string on chat messages. Where an agent acts autonomously, v0.3
  substitutes capability fencing for identity. glossql's
  actor-rides-the-connection is genuinely new; `Session::new(store,
  actor)` already is its implementation.
- Its result wire is columnar JSON frames — a workaround for a driver
  with no Arrow surface (`stream-sql.ts:10-16`), not a design to copy;
  our batches are already Arrow.

## Built

`crates/serverd` (`glossql-serverd`, binary `serverd`):

- **Plane** — store + lake + rhai runtime + sessions keyed by actor,
  created on first sight, kept for the server's life. The 2026-07-28
  MCP revision serves streamable HTTP statelessly (transport sessions
  removed), so continuity lives here — which is also what `USE` needs
  between an agent's tool calls.
- **`/mcp`** — rmcp 3.1.0 `StreamableHttpService` mounted in axum;
  `GlossqlMcp` implements `ServerHandler` by hand (one tool needs no
  macro router). Actor = initialize `clientInfo.name` (rides `_meta`
  per-request in the sessionless revision), boot `--agent` fallback.
  A failed statement is a tool error the agent reads, never a protocol
  error.
- **`/query`** — a single query streams
  (`application/vnd.apache.arrow.stream`, chunked): batches encode
  through arrow-ipc's `StreamWriter` as the engine produces them, a
  bounded channel is the backpressure. Statement sequences and writes
  answer in the wire JSON shape; refusals answer in the body.
- **Wire shape** — outcomes as JSON. Rows through the MCP door are
  capped because a tool result lands verbatim in the agent's context
  window; `row_count` and a declared `truncated` say when a result is
  bigger than shown, so the agent refines (aggregate, LIMIT, WHERE)
  instead of reading a capped result as complete.
- **Staging fix** (the M3 obligation): `__glossql_staged` takes a
  per-materialization suffix from an atomic counter — the doors cannot
  guarantee statement order.
- Versions ride the lockstep: arrow-ipc/arrow-json 58.4 (the arrow
  datafusion 53.1 pins), rmcp 3.1.0, axum 0.8.

Verified: 90 workspace tests green (6 door tests — Arrow IPC
round-trip, statement-sequence JSON fallback, refusal-in-body, MCP
initialize + tools/list, tools/call with tool-error refusal, cap with
declared truncation), clippy clean, and live smokes: the binary booted
a fresh workspace, `/mcp` answered initialize over curl, and a
1000-row query left `/query` with `transfer-encoding: chunked` — the
stream is real, not a buffered body.

Sessionless-transport facts learned in rmcp source (recorded because
every client must honor them): non-initialize requests carry
`_meta["io.modelcontextprotocol/protocolVersion"]` and
`…/clientCapabilities` (`…/clientInfo` optional — it is where the actor
rides), plus `Mcp-Method` and, for `tools/call`, `Mcp-Name` headers;
the transport's rebinding guard requires `Host` in its allowlist
(localhost by default).

## Second slice: the abstention convention and the skills folder

**Abstention names what's missing (ruled 2026-08-04, field name
`missing_aspects`).** When an accepted aspect's context entry is null,
the reference scripts now abstain with
`{"applicable": false, "missing_aspects": ["column_profile"]}` — the
entries are aspect names straight from the `ACCEPTS` clause, so the
name says what the list holds and the remedy is literal: run the
function whose `RETURNS` binds the named aspect. A bare
`{"applicable": false}` keeps its meaning: the subject genuinely
doesn't fit. The convention forced `outliers.rhai` to split the branch
that conflated the two facts; the fixture-11 test now runs `outliers()`
before `profile()` (the agent-using-functions-wildly case), reads the
named gap from the glossary, and watches the profile's landing heal it
through the declared edge. Schemas stay shape-descriptive —
`missing_aspects` rides the open remainder, `applicable` stays the one
required key.

**Skills folder** (`.claude/skills/`, loaded by any Claude Code session
rooted here; the API skills beta takes the same files later, bundling
the pointed-at artifacts at upload):

- `glossql` — the door, the outcome shape, the statement set as a
  table of pointers into SPEC.md sections, and the live-state reads.
- `glossql-add-source` — the flow playbook over
  `corpus/11-flow-add-source.md`: probe, recipe, land, measure (with
  the abstention convention), gloss, frame, read back.
- `glossql-functions` — the script contract (`subject`, `context`,
  `db`), the kernel list (authoritative list: the registrations in
  `crates/scripts/src/lib.rs`), abstention, detectors, the reference
  scripts as exemplars.

SPEC.md §8 was aligned to the ruling in the same slice: "the skill set
mirrors the statement set" (pre-M5) became "the door tells, skills
teach" — skills organized by what an agent learns, sourced from the
repo artifacts.

**Gap, surfaced not built:** "everything live is read through the
language" is ahead of the store — `glossary`, `cache`, and `imports`
are readable relations, but declared functions, aspects, witnesses,
and sources are not (`Store::relation_rows` rejects them). The skills
teach only the reads that exist. (Filled the same day — third slice
below.)

## Third slice: the mirror closes

- **Declaration relations readable** (the gap above, endorsed by the
  project lead): `functions`, `aspects`, `witnesses`, and `sources`
  answer as plain tables beside `glossary`/`cache`/`imports` — an
  agent lists what exists instead of being told. `accepts` serves the
  stored JSON array; `scope` collapses NULL to `GLOBAL`.
- **The kernel list cannot drift** (the project lead's mirror
  question): the glossql-functions skill carries the kernel list
  inline, and a test compares it against what the engine actually
  registers — rhai's `gen_fn_signatures` (metadata feature,
  rhai-1.25.1 `api/register.rs:737`; standard packages excluded, so
  only our registrations remain), enabled through a self
  dev-dependency so the shipped library never carries it. Add a kernel
  and forget the skill, or teach a phantom kernel, and `cargo test`
  fails — the same invariant that keeps SPEC.md's sql blocks parsing.
- **Static bootstrap, embedded** ("define the system statically"): the
  shipped system — the four reference scripts and the measurement
  library's declarations (`crates/scripts/functions/bootstrap.glossql`)
  — rides the binary and materializes into a fresh workspace at boot:
  scripts land under `functions/` when absent, declarations run once
  while none exist. The vertical (semantic aspects, witnesses) is
  deliberately not shipped — framing it is the agent's work, per the
  acceptance ruling. The `--functions` flag retired with it: the
  runtime's root is the workspace, so declarations reference scripts
  exactly as the corpus spells them (`'functions/profile.rhai'`).
- **MCP resources: tried, reversed the same day** (project lead). The
  elegant fork — twelve compile-time artifacts served as resources —
  was built and then removed on review: a second teaching channel
  orthogonal to skills, and it served corpus fixtures, which are
  transcription records ("what was dropped and why") with zero
  operational value to a working agent. The teaching layer is one
  thing again: skills. What survives is the embedded bootstrap — the
  binary still carries the shipped system.

## Fourth slice: the skills carry the content

The same review named the real gap: the skills taught the flow's
*shape* but not the *content* the agent must produce per column.
Grounded in v0.3's contract — `ColumnSemanticOutput`
(`analysis/semantic/models.py:29`), the schema the semantic_per_column
LLM fills: `semantic_role` (key | measure | dimension | timestamp |
attribute; judged from the table alone, foreign keys excluded),
`entity_type`, `business_term`, `description` (one business sentence,
stock/flow banned from the prose), `temporal_behavior_claim`
(stock | flow | unsure), and two confidences.

Transcribed into the add-source skill as a static framing block plus
per-column glossing rules:

- `meaning {value, term}` ← description + business_term, with the
  one-home rule (no stock/flow in prose).
- `role {value: key|measure|dimension|timestamp|attribute}` ←
  semantic_role, same judgment rules; a foreign key is never a role —
  references are `DECLARE RELATIONSHIP`.
- `behavior {value: stock|flow}` ← temporal_behavior_claim; "unsure"
  becomes *no gloss* — absence is a visible `unassessed` row, the
  model's honest form of "do not guess".
- `unit {value, source_column}` — fixture 11's spelling.
- Witnesses `BY (AGENT, HUMAN)` on all four; `slot_entropy` detector
  (THRESHOLD 0.7) on the value-bearing three, none on `meaning` —
  prose is opaque.
- Dropped in transcription: `entity_type` (its own examples duplicate
  the column name and term) and the confidence pair (calibration left
  the model 2026-08-03; adjudication lives in witnesses).

The plan (project lead, 2026-08-04): statically write what the agent
needs into the skills · test the MCP integration · monitor what the
agent actually sends · only then think about dynamic assembly (skills
generated at build is one candidate). Corpus fixtures stay design
artifacts — the skills no longer point agents at them.

## Run setup (2026-08-04, for the acceptance run)

- **Batch statements confirmed as the write path**: the tool takes a
  whole script; parse errors refuse the batch before anything runs,
  runtime refusals are fail-fast (earlier statements landed), and
  supersession makes fix-and-resend harmless. Reads belong in their own
  call — a query inside a batch is collected, not streamed.
- **Metadata reads uncapped** (ruled): a lone query whose every
  relation is the store's — `GLOSSARY()`, `ATTEST()`, the plain
  relations — streams past `--row-cap`; the map arrives whole, the cap
  guards data. Classified at parse time (`reads_only_metadata`,
  sqlparser `visit_relations`); constant selects and VALUES stay
  capped.
- **The relation shapes live once**: the store's `RELATIONS` table
  (name, columns, SQL side by side) is the single home; the read
  planner, the wire schema, and the cap classifier all derive from it.
- **The monitor**: the door prints `glossql <- actor: statements` per
  tool call and `glossql !! actor: error` per refusal — the terminal
  running serverd is the live trace of what the agent sends.
- The macOS `__eh_frame > 16MB` linker note is allowed workspace-wide
  (`linker_messages`) — a debug-binary size artifact, nothing
  actionable.
