# The f1 run — evaluation record and the redesign it forced

Date: 2026-08-06. Run 5: a fresh workspace over RelBench rel-f1
(9 parquet tables, 84,599 rows, `~/glossql-data/f1`, the relbench
distribution untouched), the first dataset the planes did not grow up
on. The run graded the framework both ways: the judge pattern held;
the measurement engineering did not, and patching it was refused by
the project lead in favor of a redesign from the literature ("find an
algorithm that works from research; the expensive places are obvious,
no test run needed"). This record replaces the intermediate patch
story; the patches that survived are listed at the end, the ones the
redesign made dishonest were reverted.

## What the run got right

- 9 recipes, 0 rows dropped; authored typing (snake_case, `\N`
  sentinel → NULL, float-encoded ints → BIGINT, a 100%-redundant
  column dropped).
- 329 current glosses; all 198 attested slots green.
- All 16 candidate edges verified by anti-join; fact-to-fact orphans
  grounded as populations (of 1,864 results without qualifying, only
  59 sit in a race that has qualifying).
- **All 11 hierarchy candidates rejected, correctly** — ten were
  `race_id ↔ date` aliases, the coincidence trap the skill names; the
  eleventh (`circuit_id → name`) failed on meaning (the French GP ran
  at 7 circuits).
- **The `points` duality found and reconciled by hand**: a flow in
  `results`, a stock in the standings tables — 25,084 of 25,520 rows
  equal the season cumulative; the 436 residuals split into sprint-era
  and dropped-scores populations.
- `results` grain is `result_id`, not `(race_id, driver_id)` — 91
  shared drives, clustered 1950–58.

## The redesign, grounded

**detect_relationships is inclusion-dependency discovery** — a solved
problem the script had reinvented badly (one two-sided DISTINCT join
per pair: quadratic engine round-trips; f1's 34 Int64 columns → ~1,100
pairs → timeout). The literature: SPIDER (Bauckmann et al. 2006),
SINDY (Kruse et al. 2015), BINDER (Papenbrock et al., VLDB 2015),
bottom-k/KMV synopses (Bar-Yossef et al. 2002; Beyer et al. 2007).
The build: every candidate column's distinct values land once
(batched engine DISTINCT, projection pushdown) as a **sorted typed key
vector** — values keep their identity for integer-like types, FNV-1a
for byte-backed ones; no display strings, no per-value allocation —
and containment between two columns is a **linear merge in the kernel**
(`key_vec`/`matched`). The statistic is **containment, not Jaccard**
(the lead's challenge was correct: Jaccard was proposed because he had
named it — the literature says containment is the join-discovery
statistic; Jaccard punishes exactly the size-skewed pairs real FKs
are). Exact while Σ distinct fits memory (~1.2 MB on f1); the ladder
past that — BINDER hash-range partitions, then KMV sketches — is
named in the script header, not built until a dataset needs it.

Two algebra-implied prunes, zero recall lost: a to side under half
the from side's distinct count cannot reach the 0.5 containment bar;
a composite scope whose legs' cardinality **product** cannot reach
the 0.9 near-unique floor can never key the table (this one dissolved
the rescue's attempt space — dense small-int columns proposing each
other as scopes). The composite rescue's two-column domains ride the
same kernel (`pair_keys`), its phase-3 SQL joins deleted.

**behavior_evidence's loop nest is a matrix product.** Per entity,
conventions w ∈ {0,±1}ᵏ against series y and event-sum matrix M —
evaluating all of them is one GEMM over the stacked entity series
(f1: 25,520 cells × 11 terms × 121 conventions ≈ 34M flops) plus
segmented L1 reductions under the ported gates. The `reconcile`
kernel (faer for the product — the algebra nugget the lead authorized
on 2026-08-05) owns alignment (hash join on typed keys), conventions,
residuals, votes; the script keeps policy — anchors, axes, grain,
term selection, Wilson support, winner. The interpreter's op backstop
went back to **50M**: raising it to 2B had been covering for the
wrong design.

## What the redesigned statistics found on f1

- **A stock that resets is a stock only inside its scope.** At raw
  driver grain the wrong-anchor gate abstained on
  `standings.points` — correctly: every season boundary injects a
  full season's error (only single-season careers voted). The real
  entity is (driver, season). Each alignment is now served raw AND
  year-scoped; the scoped anchor reconciles exactly (verdict stock,
  convention `points`, day grain). The same shape is a **year-to-date
  balance** in the finance domain — the reset reality is general, and
  the skill teaches reading the anchor pair together.
- `circuits.location → country` arrives as an edge (the exact-unique
  pool gate fix), `race_id ↔ date` alias bait still arrives for the
  judge to kill — recall intact.

## Standing decisions from this episode

- **Test policy** (lead's rule): nothing in the default suite blocks
  minutes. The f1 oracle is an evaluation, `#[ignore]`d, run
  explicitly at milestones with timings recorded here.
- **Kernel convention sharpened** in glossql-functions: a script that
  nests loops over rows or pairs is reaching for a kernel; scripts
  orchestrate and hold policy.
- Survivors from the patch round: `sql_all`/`query_all` (concurrency
  lives in the door — rhai has no threads by design), `floats()`, the
  identifier-leg exclusion, own-axis preference, coarser-of-both
  grain, the viability probe, the hierarchy pool gate, the pinned
  rhai expression depths, and the dimensions-skill correction
  (`CREATE VIEW` is refused by the substrate allowlist).
- **Views: ruled closed, same day.** The lead confirmed the earlier
  decision — grain-checked joins are the construct, in the spirit of
  the language; no persistent view object. Nothing downstream needs
  one: the remaining port (derived_formulas) is per-table; drivers
  and the operating-model metrics write their joins per query, with
  the judged-join record (relationship glosses + grain-check grounds)
  as the reusable knowledge; measurements that ever need fact-grain
  cross-table scans compose the join inside their own SQL; and the
  composite cure — the one flow that ever required a view — was
  retired by the tuple ruling (fixture 14). If a reusable spelling is
  wanted later, the language-native home would be a QUERY aspect
  carrying the judged join, proposed only when the operating-model
  phase actually asks for it.
